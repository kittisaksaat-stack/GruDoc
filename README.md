# กรุเอกสาร — เว็บไซต์สำหรับฝากไว้บน GitHub Pages

ไฟล์ชุดนี้ทำให้เมื่อผู้ใช้เปิดลิงก์เว็บนี้แล้วกด **"เพิ่มไปยังหน้าจอโฮม" / "Add to Home Screen"**
บน Android, iOS, iPadOS, macOS (Safari, Chrome, Edge ฯลฯ) จะขึ้นไอคอน "กรุเอกสาร" และชื่อแอปให้อัตโนมัติ

## ไฟล์ในชุดนี้

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `index.html` | หน้าเว็บหลัก มี meta tag ครบสำหรับ favicon/ไอคอนทุกแพลตฟอร์ม ทำงานแบบ "หน้าชวนติดตั้งไอคอน" (ดูหัวข้อด้านล่าง) |
| `site.webmanifest` | Web App Manifest สำหรับ Android/Chrome |
| `favicon.ico` | ไอคอนแท็บเบราว์เซอร์ (รองรับเบราว์เซอร์เก่า) |
| `favicon-16x16.png`, `favicon-32x32.png`, `favicon-48x48.png` | ไอคอนแท็บเบราว์เซอร์ขนาดต่าง ๆ |
| `apple-touch-icon.png` | ไอคอนตอนกด Add to Home Screen บน iOS/iPadOS/macOS Safari |
| `android-chrome-192x192.png`, `android-chrome-512x512.png` | ไอคอนสำหรับ Android/PWA |

## วิธีนำขึ้น GitHub Pages

1. สร้าง repository ใหม่ (หรือใช้ของเดิม) แล้วอัปโหลดไฟล์ทั้งหมดในชุดนี้ไว้ที่ **root** ของ repo (หรือโฟลเดอร์ `/docs` ก็ได้ถ้าตั้งค่า Pages ให้ตรงกัน)
2. เข้า **Settings → Pages** ของ repo แล้วเลือก branch/โฟลเดอร์ที่ใช้ deploy
3. รอสักครู่ GitHub จะให้ลิงก์ เช่น `https://ชื่อผู้ใช้.github.io/ชื่อ-repo/`
4. เปิด `index.html` แก้บรรทัด `og:url`, `og:image`, `twitter:image` ให้เป็น URL จริงที่ได้จากข้อ 3 (ตอนนี้ใส่เป็น placeholder `https://USERNAME.github.io/REPO/` ไว้ก่อน) — ส่วนนี้มีผลเฉพาะตอนแชร์ลิงก์ให้ขึ้นภาพตัวอย่าง ไม่กระทบไอคอน favicon/Add to Home Screen
5. อัปโหลดไฟล์ที่แก้แล้วอีกครั้ง เสร็จแล้วลองเปิดลิงก์แล้วกด Add to Home Screen ได้เลย

## ทำไมต้องมีหน้านี้ก่อน แล้วค่อยเข้าลิงก์จริง

ลิงก์ Google Apps Script (`script.google.com/...`) ไม่มีทางกำหนด favicon/ไอคอนเองได้ ถ้าผู้ใช้กด "Add to Home Screen" จากลิงก์นั้นตรง ๆ จะได้ไอคอนเริ่มต้นของ Google ไม่ใช่ไอคอน "กรุเอกสาร"

`index.html` เลยทำหน้าที่เป็น **ตัวกลาง** โดยเช็คว่ากำลังถูกเปิดจากไหน:

- **เปิดจากไอคอนที่ปักไว้หน้าจอโฮมแล้ว** (standalone) → ซ่อนหน้าชวนติดตั้ง แล้วโหลดแอป Google Apps Script จริงเต็มจอผ่าน `<iframe>` ในหน้าเดียวกัน (ดูเหตุผลด้านล่าง)
- **เปิดจากลิงก์/แท็บเบราว์เซอร์ปกติ** (ครั้งแรก) → **ไม่สลับไปเอง** แต่โชว์หน้าไอคอน "กรุเอกสาร" พร้อมปุ่ม:
  - "เข้าใช้งานตอนนี้เลย" — ไปหน้าเว็บจริงได้ทันทีโดยไม่ต้องติดตั้ง
  - "วิธีปักหมุดไอคอนไว้หน้าจอโฮม" — โชว์ขั้นตอนตามอุปกรณ์ (iOS / Android / เดสก์ท็อป) ให้ผู้ใช้กด Add to Home Screen จากหน้านี้ ซึ่งจะได้ไอคอนและชื่อ "กรุเอกสาร" ไปโชว์ที่หน้าจอโฮมถูกต้อง

**สรุปขั้นตอนที่ผู้ใช้ต้องทำ:** เปิดลิงก์ GitHub Pages ครั้งแรก → กด Add to Home Screen จากหน้านี้ (ยังไม่สลับไปไหน) → ต่อไปเปิดจากไอคอนหน้าจอโฮมจะเข้าเว็บจริงให้อัตโนมัติทุกครั้ง

ถ้าต้องการเปลี่ยนลิงก์ปลายทาง แก้ค่าตัวแปรเดียวในบรรทัดบนสุดของ `index.html`:
```js
var TARGET_URL = "https://script.google.com/macros/s/.../exec";
```

### ทำไมใช้ iframe แทนการ `location.replace` เด้งออกทั้งหน้า (แก้บั๊ก "เปิดสองหน้า")

เดิม `index.html` ใช้ `location.replace(TARGET_URL)` เพื่อเด้งออกจากหน้านี้ทั้งหน้าไปยัง `script.google.com` ทันทีเมื่อเปิดจากไอคอนหน้าจอโฮม แต่พบว่าบน **iOS/iPadOS (Safari)** เมื่อแอป standalone พยายามเปลี่ยนหน้าทั้งหน้าไปคนละโดเมน ระบบจะตีความว่ากำลังจะออกจากแอป แล้วดีดไปเปิด Safari ปกติเป็นหน้าต่างแยกต่างหาก ส่วนหน้าต่างแอปเดิมที่ปักไว้หน้าจอโฮมจะค้างเป็นหน้าว่างเปล่าอยู่เบื้องหลัง — ผู้ใช้จึงเห็นเป็น "สองหน้า" (หน้าแอปที่ใช้งานได้ปกติ + หน้าว่างเปล่าที่ค้างอยู่)

ทางแก้คือไม่เปลี่ยนโดเมนของหน้าต่างหลักเลย แต่ฝังแอปจริงไว้ใน `<iframe>` เต็มจอแทน (ยังอยู่โดเมน GitHub Pages เดิมตลอด) iOS จึงไม่ดีดออกไปเปิด Safari ซ้อนอีก ถ้า iframe โหลดนานเกิน 8 วินาที (เช่นเน็ตหลุด) จะมีปุ่มสำรองให้กดเปิดในเบราว์เซอร์เองแทน

## หมายเหตุ

- ไม่ต้องเปลี่ยนชื่อไฟล์ไอคอนใด ๆ เพราะ `index.html` และ `site.webmanifest` อ้างอิงชื่อไฟล์เหล่านี้ตรง ๆ
- ถ้าต้องการเปลี่ยนสีธีม (theme color) แก้ค่าที่ `theme-color` ใน `index.html` และ `theme_color`/`background_color` ใน `site.webmanifest`
